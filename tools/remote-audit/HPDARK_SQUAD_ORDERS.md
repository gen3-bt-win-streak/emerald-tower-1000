# ラグ技変種（冷B→めざ悪70）A/B マラソン — 班（squad）作戦指令

**目的**: ラグラージの「れいとうビーム → めざめるパワー(あく70)」変更の勝率影響を、
関所3・BOOM_FIX・FIRE_FIXと同じ**同一100万シードのペア比較**で測る。

**背景（実機442連勝がヌケニンで停止）**:
- ヌケニン(ふしぎなまもり)に通る技は現構築で**ラグの岩雪崩のみ**（実効命中85.5%・外すと即詰みリスク）。
- ラグはALL31個体のため**めざパは自動的に「あく・威力70・命中100」**（個体値・実数値の変更ゼロ、TM10のみ）。
- めざ悪はヌケニン確1（実機HP1・シミュ217-255≥206も確1）＋ゲンガー（浮遊EQ無効）への打点も冷B27%→40%に改善。
- 失うのはラグの氷打点（実測使用率9%・ドラゴン4倍はサンダーめざ氷/ラティ冷Bで代替）。

**事前登録の合格基準（通常と異なる・非劣性試験）**:
- ヌケニンは300トレーナー中2人の激レア枠→シミュ上は**中立(net≈0)が予想値**。
- **「有意に悪化しない」なら採用**（動機は実機の尾リスク潰しであり、シミュ改善は要求しない）。
- **net>0 かつ McNemar p<0.05（冷B喪失の害が有意）の場合のみ棄却**。

OFF側＝既存ベースライン（`v4m_ckpt_*.json` 合計2516敗）を再利用し、**ON側（`hdm_ckpt_*.json`）だけ**を回す。

- ON側エンジン: `sim_hpdarkmarathon.py`（sim_v4marathon のコピー＋ラグ技表差し替えのみ。envフラグ無し・ボットロジック同一）
- ペア集約・裁定: `aggregate_hpdark.py`

## 各班の実行手順（自分のBASEに置換）
```bash
cd battle-tower/tools/remote-audit
git pull --rebase origin claude/battle-tower-1000-wins-8xr0ze
chmod +x shepherd_hpdark.sh
nohup ./shepherd_hpdark.sh 25000000 > shepherd_hpdark_run.log 2>&1 &   # 班A=25M/班B=26M/班C=27M/班D=28M
```
- **必ず `PYTHONHASHSEED=0 FIDELITY2=1`**（shepherdが各ワーカーに設定済み）。
- ckpt（`hdm_ckpt_*.json`）は追跡・コミット対象。ログは.gitignore済み。
- ~30分〜完走ごとに耐久化: `git add hdm_ckpt_*.json && git pull --rebase --autostash && git commit -m "hdm-ckpt" && git push`。
