# 21. 乱数オラクル — 観測からのシード同定と敵の完全先読み【2026-08-25・着手】

> **目的**：タワーの戦闘は「開始時の乱数状態＋入力列の純粋関数」（03章§5.2）。
> ならば**観測（トレーナー名・先発2体）から逆に乱数状態を同定**すれば、
> 敵4体の型・技・持ち物・以降の行動まで**ターン1の入力前に全て計算できる**。
> セーブに一切触れない**純粋な観測＋計算**であり、PKHeXとは別軸のアプローチ。
> ツール：`tools/rng-oracle/`（towergen.py＝生成の忠実移植／identify.py＝同定）

## 1. 理論的裏付け（03章§5.2の帰結）

1. **戦闘中**：`VBlankCB_Battle` の毎フレーム消費が `BATTLE_TYPE_FRONTIER` で無効
   ＝消費は戦闘ロジックの呼び出し回数だけで決まる（バトルビデオが再生可能な理由そのもの）
2. **戦闘間**：毎フレーム消費（約60回/秒）が復活。ただし**バトルルームに徘徊NPCはゼロ**
   （map.json原文確認：オブジェクト3体すべて `MOVEMENT_TYPE_FACE_*` 固定向き）
   ＝**戦闘間の消費は「経過フレーム数」だけの1次元**。A連打で会話数固定なら窓は狭い
3. **ロビーには徘徊NPCが2体**（`MOVEMENT_TYPE_WANDER_AROUND`×2）
   ＝挑戦開始前（1戦目の同定）だけは徘徊消費のノイズが乗る。2戦目以降はクリーン

## 2. 敵生成の消費構造（battle_tower.c / pokemon.c 原文移植）

連勝49以上の定常域・ダブル・オープンレベル・記録ミックス無しのセーブで：

| 段階 | 消費 | 内容 |
|---|---|---|
| トレーナー抽選 | 1×試行 | `200 + Random()%100`。挑戦内で戦済みIDは引き直し |
| （会話・演出） | 経過フレーム数 | 1消費/フレーム |
| OTID | 2 | `Random32()`＝**下位半分が先** |
| セット抽選 | 1×試行 | `monSet[Random()%n]`。種族重複・持ち物重複・同一indexで棄却 |
| PID生成 | 2×試行 | 採用セットごとに**性格一致まで** `Random32()` 棄却ループ（期待約25試行＝約50消費/体） |

実測（2万戦MC）：1戦の生成消費は **min 20 / 中央値 321 / max 817**。
`ChooseSpecialBattleTowerTrainer` は記録ミックス無しなら**消費ゼロでFALSE**（原文確認）。

## 3. データの相互検証（全て一致）

- 抽出した**ID200-299のプール和集合＝ちょうど546セット**（既存の定常プールと完全一致）
- `frontier_sets.csv` の `lategame_trainer_count` 列を抽出プールから再計算 → **882セット全行一致**
- 2万戦の生成で種族重複ゼロ・持ち物重複ゼロ・プール外セットゼロ

## 4. 同定の一意性（実測）

観測＝トレーナー名＋種族（セット構成は見えない前提）で、真の状態の周囲を走査：

| 窓幅 | 観測 | 一意同定率 | 偽陽性 平均 |
|---|---|---:|---:|
| **±100（A連打精度）** | 先発2体 | **33/40** | 0.25 |
| ±3600（±60秒） | 先発2体 | 5/40 | 26.3 |
| ±3600 | 3体判明 | 8/15 | 1.5 |
| ±3600 | 4体全部 | 10/15 | 0.33 |
| ±30000（±8.3分） | 4体全部 | 4/6 | 1.0 |

- **A連打で窓±100に収めれば先発2体だけでほぼ一意**。
- 残る偽陽性の内訳は**別セット構成7：同一構成1**（±3600・4体一致時）＝
  **技・持ち物が違う別解**なので、戦闘中に技を1つ目撃した時点で消える
  （同一構成の偽陽性は予測が同じ＝実害ゼロ）
- 窓が広くても、敵の初手・控えの登場で観測ビットが増えるたびに単調に絞れる

## 5. 使い方

```bash
cd tools/rng-oracle
python3 extract_trainers.py     # 初回のみ: frontier_trainers.json 生成
python3 towergen.py 0x12345678  # その状態からの敵生成を表示
python3 identify.py --trainer JAXON --leads Marowak,Hariyama \
    --center 0x12345678 --radius 200   # 同定（窓走査）
```

`identify.py` は一致した状態ごとに**4体のセット構成・技・持ち物・生成後の状態**を出力する。
生成後の状態が次の戦闘の同定の**アンカー**になる（§1-2＝戦闘間は1次元のフレーム消費のみ）。
